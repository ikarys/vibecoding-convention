Let’s vibecode properly.

A checkable standard for software written with AI assistance. The evidence lives in your repository, and anyone can check it.

Read the convention Adopt it

The problem is not AI

AI-assisted code is not a problem. Unframed, unreviewed, unaudited code is, whoever or whatever wrote it.

The convention says what framed, reviewed and audited mean in terms anyone can verify, and what evidence a project keeps to back the claim. Each requirement answers a criticism actually made of vibecoded software.

Transparency over purity
Say what the AI wrote; nobody is asked to avoid AI.
Evidence over claims
Every requirement names an artifact or a command anyone can run.
Proportionality
A project picks the level that fits and proves it.
Humans decide
AI proposes; a named human validates, decides and is accountable.
Outcomes, not forms
The convention says what must be visible, never which tool to use or how to work.

Three levels, each including the one before

A project picks a level and proves it. Nobody is asked to reach level 3 for a weekend script.

Each level includes all the requirements of the levels inside it.

3

Audited

You do: level 2, plus versioned audits in the repository: architecture review, security audit, blind usability test, validated architecture documents, each finding with a decision.

It proves: someone other than the author looked, and what they found is on record.

Costs a few hours per release, repeated. Fits anything that handles other people's data, money or safety.

The 8 requirements
  • A1 An architecture review with a verdict, renewed at each structural change.
  • A2 SECURITY.md with a threat model; every security claim traced to a passing test.
  • A3 A tester with no access to the source uses the software from the docs alone.
  • A4 audit/README.md indexes every report; reports are appended to, never rewritten.
  • A5 No release with an open BLOCKER or DOC-WRONG; a named human approves it.
  • A6 Architecture overview and decision records, validated by a named human.
  • A7 Mutation score measured on the core modules (recommended).
  • A8 Everything with repository access is versioned, reviewed, pinned and free of secrets.
2

Tested

You do: level 1, plus tests, coverage, lint, secrets scanning, static analysis and dependency checks in CI, their results committed as evidence behind a dated badge.

It proves: the code behaves as claimed and is checked on every change, not once.

Costs a day or two of CI set-up, then it runs itself. Fits anything others depend on.

The 12 requirements
  • T1 Tests run in CI on every change.
  • T2 Coverage is measured and meets the declared threshold.
  • T3 Tests assert behaviour; none is skipped without a reason.
  • T4 User-facing software has end-to-end tests of its main journeys.
  • T5 Lint and format run in CI and fail on warnings.
  • T6 Lockfile committed; vulnerability, licence and registry checks on every dependency.
  • T7 A secrets scanner and a static analyser run on every change.
  • T8 Duplication, complexity and size are measured against declared thresholds.
  • T9 Dependencies are current and none is unmaintained, or the exception is declared.
  • D5 A dated status file, written by the check, feeds the badge and goes stale on its own.
  • D6 Deleting or weakening a test is explained and approved by a human.
  • D10 Agent instruction files carry the level, the commands to pass and what the agent never does alone.
1

Declared

You do: say that AI wrote part of the project, with which tools and models, who decides, how you take contributions and your licence stance. Tag AI-written commits. A human reviews every change.

It proves: nothing is hidden: who wrote what, who is accountable.

Costs an afternoon. Text only, no tool to install. Fits scripts, prototypes, anything public.

The 7 requirements
  • D1 README says AI helped and links to the declaration.
  • D2 VIBECODING.md states the level, the tools and models, who decides and how changes are reviewed.
  • D3 AI-written commits carry a trailer naming the tool and model.
  • D4 A human reviews every AI-written change before it lands.
  • D7 Licence, copyright stance on AI-written parts and provenance safeguards are stated.
  • D8 CONTRIBUTING.md says how AI contributions are received and which trailer to use.
  • D9 Project status and security response time are stated and match SECURITY.md.

Requirements in bold are the core of a level: the ones that make it. The others consolidate it. All are required: a project that cannot meet one says so, and why, under Exceptions in its VIBECODING.md. The convention is not à la carte, but it never asks for silence.

Most of this is what a careful human-led project already does. Six requirements exist only because AI is involved: D1, D2, D3, D7, D10 and A3; all but A3 are text. The recorded registry check in T6 is there for the same reason.

Every requirement, its evidence and how it is checked

Sending a contribution elsewhere

Most of the harm blamed on vibecoding comes from single contributions: a generated pull request sent unread, a bug report nobody reproduced. Five rules apply to anyone, person or agent, contributing to a project they do not maintain.

  • C1

    Disclose: say that AI helped, with tool and model, in the text and as the trailer the project expects.

  • C2

    Know your diff: be able to say what each change does, why, and what it affects.

  • C3

    Bring the proof: tests and docs with every behaviour change; reproduce what you report.

  • C4

    Respect the project: follow its guide and AI policy; one change per pull request.

  • C5

    Answer review yourself, in the time the project expects.

Adopt it

  1. Add a VIBECODING.md declaration at the root of your repository, a CONTRIBUTING.md naming your trailer, a SECURITY.md with your response time, and a README line linking to the declaration. The badge comes with level 2.

  2. Attribute AI-written commits with a trailer naming the tool and model:

    Assisted-by: Claude Code:claude-opus-5-5

  3. Run the checks for your level and keep the reports under audit/.

    vibecheck, a validator with no AI in it, reads the declaration, the repository and the evidence your CI wrote, and never runs your code.

Tooling is optional. A project can meet the convention by hand.
